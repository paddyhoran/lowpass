# Architecture Design Document: Local Deterministic Tool Calling Framework

## 1. Executive Summary
This document outlines the architecture for building a 100% local, ultra-low-latency, and deterministic
tool-calling framework. Instead of relying on generative Large Language Models (LLMs) this framework 
utilizes a **Joint Intent Classification and Slot Filling** approach.

By fine-tuning a micro-encoder model (e.g., `BERT-Tiny` or `MiniLM`), the system achieves sub-10ms
response times and strictly adheres to predefined tool schemas.

---

## 2. Core Model Architecture: The Dual-Head Encoder

The system operates via a single forward pass through a lightweight Transformer encoder, topped with
two independent, parallel classification heads. 

```text
                          ┌─> [Head 1: Intent] ──> Predicts Tool (e.g., `set_alarm`)
[ User Input String ] ────┤
                          └─> [Head 2: Slots]  ──> Predicts Params (e.g., "7:00 AM" = time)
```

### 2.1 The Components
*   **The Encoder Brain:** Converts the raw input string into dense mathematical vectors (embeddings)
capturing the semantic meaning of the sentence.
*   **Head 1 (Intent Classifier):** A linear layer operating on the sentence-level embedding. It 
outputs a probability distribution (Softmax) over all registered tools.
*   **Head 2 (Slot Tagger):** A linear layer operating on the token-level embeddings. It performs
BIO (Begin/Inside/Outside) sequence tagging to map individual words to specific parameter types.

### 2.2 Parallel Execution & Schema Filtering
Head 1 and Head 2 execute **independently and simultaneously** to maximize speed. Because Head 2 selects
from a global vocabulary of tags across all tools, it may occasionally predict a tag belonging to a
different tool. 

**Resolution:** This is resolved deterministically at the application layer using **Schema Filtering**. The
application takes the predicted tool from Head 1, looks up its valid parameters, and automatically drops or
remaps any incompatible tags generated by Head 2.

## 3. The Rust Implementation Stack

The framework is built natively in Rust to leverage zero-cost abstractions, memory safety, and microsecond-level
execution.

### Crates
| Component                  | Crate                  | Purpose                                                                                                                                                           |
|:---------------------------|:-----------------------|:------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Model Graph / Training** | `candle`               | Runs and trains the model graph (via `candle`'s own autodiff), 100% pure Rust/WASM-compatible                                                                     |
| **Tokenization**           | `tokenizers`           | Converts strings to model tokens. Crucially provides **offset mappings** to precisely map extracted slots back to exact character indices in the original string. |
| **Matrix Math**            | `ndarray`              | Handles raw logit manipulation, `argmax` resolution, and Softmax score calculations.                                                                              |
| **Schema/Validation**      | `serde` + `serde_json` | Enforces strong typing for tool schemas and deterministic JSON generation.                                                                                        |

### Data Structures & Logit Masking
Use standard Rust slices or bitmasking to set disallowed tool logits to `f32::NEG_INFINITY` prior to
calculating the Softmax. This executes in nanoseconds and guarantees the model cannot select a
deactivated tool.

## 4. Training Strategy (Native CPU Training)

The model can be fine-tuned entirely locally.

### Framework

**`candle`** is used for both training and inference.

### Training Hardware Requirements
Because the model architectures are exceptionally small, **no GPU is required**.

*   **Model Sizes:** Models like `BERT-Tiny` (~17MB) or `all-MiniLM-L6-v2` (~90MB) are 100x–1000x smaller than local generative LLMs.
*   **Training Time:** Full model fine-tuning on a dataset of 1,000–5,000 examples takes just **1 to 3 minutes** on a modern multi-core CPU. 
*   **Head-Only Tuning:** Freezing the encoder and only training the two linear heads reduces training time to **5 to 15 seconds**.
